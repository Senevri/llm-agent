# LLM Agent Framework

A modular system for autonomous AI agents and interactive REPLs, designed to interact with OpenAI-compatible APIs (like Ollama) and manage local system resources.

Readme generated by the agent/REPL

## 🚀 Getting Started

### Installation & Setup
1. **Build the Environment**: Run `build.bat` (or convert to `.sh` for Linux/macOS).
2. **API Configuration**: Ensure an OpenAI-compatible API endpoint is available.
3. **Launch Sandbox**:
   ```bash
   podman compose run --rm sandbox
   ```
   This launches a BASH shell inside the container.
4. **Environment**
   - Export `OLLAMA_BASE_URL` and `OLLAMA_PORT` if using a custom Ollama setup.
5. **Configuration**: Prompts can be edited directly in the host filesystem for persistence.

## 🛠 Core Interfaces

### 1. Autonomous Agent
An agent that iterates through a task using tool-calling and a feedback loop.

- **Entry Point**: `python3 /agent/run_agent.py`
- **Prompting**:
  - **Automatic**: By default, it utilizes the `PromptGenerator` to load roles.
  - **Manual Override**: You can specify custom files via CLI arguments.
- **CLI Parameters**:
  - `--backend`: `ollama` or `mistral` (Required)
  - `--role`: Specifies the agent role for the prompt generator (Default: `agent`)
  - `--system-prompt`: Path to custom system prompt file (Overrides generator)
  - `--user-prompt`: Path to user task file (Default: `user_prompt.md`)
  - `--model`: Override the default model name
  - `--max-turns`: Max iteration limit (Default: `100`)
  - `--context-limit`: Context window limit (Default: `100`)
  - `--log-level`: Logging verbosity (e.g., `DEBUG`, `INFO`)

### 2. LLM REPL (Profiled)
An interactive chat interface featuring a background **Profiling Agent** that maintains a persistent JSON profile of the user's preferences, goals, and expertise.

- **Entry Point**: `python3 /agent/llm_repl_profiled.py`
- **Key Features**:
  - **Dynamic Profiling**: Automatically updates `.llm_user_profile_v2.json` based on user interactions.
  - **Integrated Tools**: Bash execution, File I/O, Internet search, and Weather.
  - **Job Dispatching**: Ability to spawn autonomous agents in the background via `dispatch_agent`.
- **Interactive Commands**:
  - `/q`: Quit the REPL.
  - `/clear`: Reset conversation history.
  - `/sys <prompt>`: Manually set the system prompt.
  - `/role <name>`: Switch the agent role using the prompt generator.
  - `/model <name>`: Change the active LLM model.
  - `/profile`: Display the current user profile JSON.
  - `/history`: Show the conversation context in a table.
- **Configuration (Env Vars)**:
  - `LLM_REPL_MODEL`: Model ID (Default: `gemma4:e4b`)
  - `LLM_REPL_PROFILE_PATH`: Path to user profile JSON
  - `LLM_REPL_MAX_CONTEXT`: Number of messages to keep in history (Default: `40`)

## 🏗 Architecture

### Core Framework
- **`prompt_generator.py`**: Centralized logic for generating system prompts based on roles.
- **`system_prompt.md`**: The master definition of agent behavior and safety constraints. Superceded by prompts folder.
- **`user_profile_manager.py`**: Persistence layer for user preferences and session context.

### Tooling Modules
The agent's capabilities are decoupled into specialized modules:
| Module | Purpose |
| :--- | :--- |
| `bash_tools.py` | Shell execution and filesystem management |
| `internet_tools.py` | Web search and content extraction |
| `tmux_tools.py` | Detached session management for long-running tasks |
| `agent_deb_tools.py` | Debian package installation without root |
| `context_tools.py` | Context retrieval and memory management |
| `agent_tools.py` | General purpose utility tools |

### Modular Skill System (`/agent/skill_system`)
A higher-level abstraction allowing the agent to execute complex "Skills" composed of multiple tools:
- **`tool_registry.py`**: Central manifest of all available tool specifications.
- **`skills_manager.py`**: Logic for loading and executing complex skill chains.
- **`integration.py`**: Connects the skill system to the primary agent pipeline.

### Infrastructure Utilities
- **LLM Management**: `llm_utils.py` and `model_catalog.py` handle API abstraction and model selection.
- **Stability**: `openai_error_handling.py` provides robust retry/error logic for API calls.
- **Observability**: `custom_logger.py` manages detailed execution traces.
